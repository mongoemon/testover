ในโปรเจกต์ครอบคลุมอะไรบ้าง

ไฟล์จดไว้ว่า
validation.spec.tsขอบเขตของทุกฟอร์ม: ความยาว username (3 ถึง 20 ตัว, ใช้ได้เฉพาะตัวอักษร ตัวเลข underscore), รหัสผ่านขั้นต่ำ 8 ตัว, ชื่องานไม่เกิน 80 ตัว, ลำดับการตรวจ (ตรวจ username ก่อนรหัสผ่าน ตรวจรหัสเดิมก่อนความยาวก่อนการยืนยัน), username ไม่สนตัวพิมพ์เล็ก/ใหญ่ แต่รหัสผ่านสนใจ, login ผิดทุกกรณีใช้ข้อความเดียวกัน
resilience.spec.tsแอปบูตอย่างไรเมื่อ storage ผิดปกติ (JSON พัง, ข้อมูลผิดชนิด, งานผิดรูปปนกับงานดี, theme แปลก) และกฎการ redirect ของแต่ละ route รวมถึง title ของแต่ละหน้า
unit/contracts.test.mjsข้อความที่ notify.mjs สร้างจากรายงานแต่ละแบบ ตรงตามตัวอักษร และรายงานที่ไม่มีเทสเลยถูกนับเป็น PASS
เคสที่ขึ้นต้นด้วย QUIRK คือพฤติกรรมที่น่าจะไม่ตั้งใจ แต่จดไว้ตามจริงก่อน ตอนนี้มี 4 เคส:
  • ชื่ออย่าง __proto__ และ constructor สมัครได้
  • ถ้า tb.users ถูกเก็บเป็น array แอปจะไม่ซ่อมให้และทุกคน login ไม่ได้
  • งานที่ข้อมูลเสียจะแค่ไม่แสดง แต่ถูกลบถาวรเมื่อมีการเปลี่ยนแปลงครั้งถัดไป
  • รหัสผ่านใหม่ถูกเก็บเป็นข้อความธรรมดา (ตั้งใจเพื่อให้เป็นแอปทดลอง)
เมื่อแก้บั๊กเหล่านี้ในอนาคต เคส QUIRK จะพัง ซึ่งเป็นสัญญาณที่ดี ให้เปลี่ยนค่าที่คาดไว้เป็นพฤติกรรมใหม่ที่ถูกต้อง
